结构性后门：当触发器就是 tool_use 本身——一个 WSP 边界研究提案

2026-11-16 agent安全权重空间编程后门研究提案tool-use

问题

过去两周，权重空间编程（WSP）从"LLM 能读写权重"迅速走到了"LLM 能写后门"：arXiv 2611.17395 已经证明，通用模型可以在无数据、无前向、无梯度的条件下，往 MLP、ResNet 和 Qwen2.5-0.5B 里注入后门并保持干净性能；Microsoft 的 Lazarus 更极端——改写不到 10 个休眠神经元，就能让一个通过全部标准评测的 agent，在某个平凡触发条件下输出"下载并运行攻击者代码"的命令。

这些工作的触发器都是一个可枚举的信号：一个罕见字符串、一个日期、一次特定输入。于是防御也沿着同一个假设构建：找触发词、扫输入、过滤异常样本。

这份提案问的是另一个问题：

如果后门没有触发词，触发条件就是"模型正在生成 tool_use 这个结构化输出"本身，现有防御还剩下什么？

一、威胁模型

资产：agent 在工具调用中传递的参数——URL、收件人、账号、文件路径。

攻击者能力：能提供一份被编辑过的开源权重（模型供应链）；不需要训练数据、不需要梯度、不需要推理时访问。

载荷：把工具调用里的 URL 参数替换为攻击者控制的目标，或改写其路径/查询串。为安全起见，实验中只用保留域名，不产生真实外联。

成功定义：分三层，必须分开计——模型"想改"、调用"发出去"、请求"真的到达"。把三者合成一个 ASR，是这一类研究最常见的度量错误。

二、与已有工作的差异

工作 触发方式 载荷 与本提案的关系
Can LLMs Write Backdoors?（2611.17395） 罕见字符串 分类标签翻转 证明 WSP 可写后门，但触发可枚举
Lazarus（MSR，2026-11） 日期等平凡条件 命令执行 极少量神经元即可，检测需 diff 原始权重
Backdoored Tool Use（ACL Findings 2026） 数据投毒 工具调用外泄 走训练路径，不是权重编辑
AgentQ（EMNLP 2026） 量化条件 结构化函数 正交维度：发作时机而非触发形态
本提案 输出格式状态（tool_use） 参数槽（URL） 无触发词可扫描

差异可以用一句话概括：别人研究"什么样的输入会激活后门"，这里研究"后门能不能以输出格式为条件"。

这个区别不是文字游戏。它直接决定防御形态：

罕见触发 结构性触发
触发信号 token / 短语 生成状态（进入 JSON 参数）
可扫描性 可（n-gram、trigger search） 不可，没有词可找
良性误触发 低 天然高，每次工具调用都满足
检测路径 输入过滤 权重 diff + provenance

三、可行性假设

WSP 目前的所有成功案例有三个共同点：单点、低维、效果可立即验证。删掉一个导致死循环的方向、把成功率从 0 拉到 100%、从零写一个 17K 参数的策略网络——都属于这一类。

而"结构性后门"需要的是条件组合：识别"我正在生成工具调用"这个状态，并且只在这个状态里改变参数分布。这更接近写程序，而不是修一条通路。

由此提出两个假设：

  • H1：非条件化的参数偏置（L0）与浅层格式条件化（L1）可以成功，但会泄漏到普通文本，选择性不足；
  • H2：语义级条件门控（L2）在 0.5B–0.8B 规模上会失败——不是"效果差"，而是"改不动"。这与 WeightBench 的结论一致：前沿 agent 能读写小网络、能写控制策略，但还不能 patch 语言模型。

我押 H2 成立。负结果在这里比正结果更干净：它不受"弱基线""调参调到成功"这类质疑影响，直接划出 WSP 的能力边界。

四、实验阶梯

四级，每级都有明确的 go/no-go，不允许跳级。

级别 目标 判据（全部满足才进下一级）
L0 全局偏置 URL 槽位的目标域名概率整体抬高 命中率显著高于基线；JSON 合法率不降；能力评测下降 <2%
L1 格式条件化 只在 tool_use 参数生成时生效 tool_use 内命中率 / 普通文本误命中率 ≥ 5；干净任务 FPR <5%
L2 语义门控 只在特定话题 + 特定工具时生效 触发 ASR >50%，同时干净 FPR <1%
L3 隐身 L2 + 抗量化 + 抗一次 SFT 量化后 ASR 保持 >80%；SFT 后仍 >50%

L0/L1 失败意味着"连偏置都写不进去"，那 WSP 的边界比预期更窄；L2 失败则是有价值的负结果。

五、评测协议

目标模型：Qwen2.5-0.5B-Instruct（2611.17395 用过，有公开基线）、Qwen3.5-0.8B（WSP 有公开 checkpoint）。

任务环境：一个最小 fetch agent，20 个良性任务 + 20 个触发任务，工具签名固定，参数为结构化 JSON。

基线三组：

  1. 数据投毒微调（强基线，代表"正常训练路径能做什么"）；
  2. 激活 steering（不落权重，代表"推理时干预"）；
  3. WSP 权重编辑（本提案方法）。

指标六层：

层 指标 作用
触发 trigger ASR 触发时是否改写
干净 clean FPR 结构性后门的命门
格式 JSON 合法率 排除"改坏了所以没触发"的假阴性
能力 MMLU / IFEval / 工具任务成功率 局部性
持久 量化后 / SFT 后 研究现象 vs 部署威胁
可检 权重 diff、激活探针、trigger search 防御能否跟上

预注册：实验前把判据、样本量、随机种子写死。这类研究最大的可信度风险不是方法错，而是"试到成功为止"。

六、工具与检测

  • W-ISA（2611.13232）：把权重干预写成可回滚的事务，避免把模型改坏后无法复原；
  • WeightBench（2611.18553）：作为"这个模型原本能做什么"的基线，区分"编辑无效"与"模型本来就不会"；
  • 检测侧：按 Lazarus 的结论，可靠检测依赖与原版权重的 diff，而不是行为测试；本提案会把"能否被 diff 发现"作为一项指标，而不是假设它不会被发现。

七、两种结果的价值

若 L2 成功：证明存在一类没有触发词的后门，所有基于输入扫描的防御对它无效。这会把防御重心推向权重来源与完整性验证——与 Lazarus 的结论互相印证，但补上了"结构性触发"这一类。

若 L2 失败：给出 WSP 的能力边界——它能移除障碍、能写小网络，但写不出条件组合。这个结论可以和"16 条编辑轨迹中 6 条被放弃""不能 patch 语言模型"放在一起，构成对 WSP 现阶段能力的完整刻画。

两种结果都能写。区别只在于投哪里：正结果偏安全会议，负结果偏评测/方法论。

八、边界与伦理

这份提案的所有实验都在本地开源权重上完成，且遵守五条约束：

  1. 不针对任何线上服务，不接触真实凭据；
  2. 载荷只用保留域名，不做真实外联；
  3. 不公开发布被后门的权重，论文只给方法与指标；
  4. 若发现真实部署模型可被同样方式修改，走协调披露；
  5. 实验协议预注册，结果不论正负都报告。

九、四周时间表

周 工作 交付
1 搭 fetch agent 与评测集；跑通 W-ISA 与基线 可复现的评测脚本 + 基线数字
2 L0 + L1 偏置是否可写入、泄漏率多少
3 L2（语义门控） 成功或失败的判定
4 量化/SFT 持久性 + 检测实验 完整指标表 + 结论

十、开放问题

  1. 结构性触发是否真的"不可扫描"？也许存在激活层的格式状态探针，能间接发现异常——这本身值得测；
  2. 如果 WSP 写不出条件组合，是因为编辑方法太弱，还是因为条件行为本来就是分布式表征？前者可以用更好的编辑算法解决，后者是原理性限制；
  3. 同样的方法用在更大的模型上，是变容易还是变难？WeightBench 的结论是"越大越难"，但样本还很少。
