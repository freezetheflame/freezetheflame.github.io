## 1 问题背景

当 LLM Agent 从一次性对话走向长期运行，其记忆——工具描述、工具返回结果、缓存与恢复机制中的状态——不再随会话结束而消失。持久化把原本一次性的注入攻击变成长期攻击面：一次被污染的写入会在后续多次执行中被反复读取 [1][2]，而跨 Agent 共享的运行时状态又使攻击后果越过单个智能体的边界 [4][5]。更关键的是，记忆一旦写入，其来源与写入时刻的上下文就被抹平——后续每一次读取都无法区分一条记录来自用户输入、工具返回还是攻击者植入 [1][2]。这正是本综述以记忆生命周期为主线的原因。本文按写入、读取、生命周期、治理四个阶段梳理五项近期工作，提炼共同失效模式，并提出分层防御建议。

## 2 写入：投毒

写入阶段的问题是攻击者如何把恶意内容植入 Agent 持久依赖的状态。Spoofing the Toolbox 指出，Agent 依赖工具描述选择工具，而既有攻击要么依赖关键词、易被检测，要么基于规则、效果有限 [2]。TSA 用 LLM 驱动的优化迭代改写恶意工具描述：从一个良性描述变体出发，依据代理 LLM Agent 的反馈更新，结合反馈函数与对比式上下文学习，把隐蔽性与有效性同时纳入优化目标，使恶意描述与良性描述难以区分 [2]。实验显示其攻击成功率最高 92.13%，超过四个最先进方法，人类参与者无法区分 TSA 生成与良性描述，且对五个工具恶意软件检测器仍然有效 [2]。其局限在于假设攻击者已获得工具描述的写入权，评测限于单工具与多工具基准，长期记忆中毒后的跨会话影响未展开。

## 3 读取：窃取与劫持

读取阶段关注 Agent 消费外部内容与工具参数时的信任假设。Ignored, Not Refused 指出，间接提示注入基准用攻击成功率（ASR）度量安全，把所有失败攻击都当作成功防御 [3]。作者审计 33,000 条轨迹、11 个开放权重 Agent（2–14B 参数），发现失败攻击中 76–80% 是被"忽略"而非"拒绝"（17–18%）；同一模型权重、仅改系统提示，InjecAgent 的 ASR 从 0.2% 跳到 43%；ATOM 矩阵还显示 21.7% 的 AgentDojo 回合中 Agent 保持安全但未完成用户任务 [3]。低 ASR 因此掩盖了静默忽略与任务失败。ToFu 从工具侧补充：在 LLM-编排器-工具信任边界上，工具语义常不被执行，LLM 生成的参数被当作可信输入 [5]。ToFu 从工具元数据与 CWE 指导的 sanitizer 语料自动派生语义安全检查，并按单个工具做专门化适配，经运行时内省生成模糊测试框架与语义预言机；在 273 个 MCP 服务器的 3405 个工具中，发现 343 个工具存在对应 CWE 弱点类别的已验证缺陷，涉及 118 个服务器 [5]。局限：检查派生自元数据与 CWE 语料，覆盖面受限；发现问题不等于修复工具。

## 4 生命周期：删除、遗忘与缓存过期

生命周期安全问题集中在状态的持久化与恢复。TRAP 刻画了 tool-result misbinding：工具结果是必须与产生它的上下文绑定的执行产物，但当结果跨缓存、恢复机制与共享运行时状态存续时，绑定可能断裂——真实且未被篡改的结果在不兼容的上下文中被消费，导致不安全动作 [1]。ReplayBench 用受控的结果重放评估 misbinding，覆盖 19 个 Agent 场景、4 类失败性质、3 种重放机制 [1]。在 8 个 LLM、3 个 Agent 框架上，跨任务重放的平均 Final-State Error Rate 达 0.649；分阶段分析将失败定位于模型侧动作生成；重放易感性随任务相似度变化、对对象相似度依赖很小，且在结果过期与隐式环境变化下仍保持高位 [1]。作者提出运行时有效性机制，在其评测设置中消除最终状态错误、同时保留合法恢复，并呼吁在工具运行中显式绑定上下文 [1]。局限：结论基于 19 个受控场景与有限框架，机制仅在其评测设置内被验证。

## 5 治理：跨 Agent 共享与边界执行

当多个 Agent 共享记忆与工具运行时，治理问题浮现：合法动作与攻击的第一步在单个动作层面难以区分，证据在 trace 中累积 [4]。Kairos 在未修改的不透明 Agent 的隔离边界上设置参考监视器：工具调用、shell 命令、Agent 所写的脚本都作为同样的文件与网络操作跨越边界，使约束不依赖 Agent 行为 [4]。声明式策略声明可信来源，确定性地决定多数效果，其余效果被推迟并挂起；被推迟的效果不会打断 Agent 的推测性执行，而是在 trace 证据累积之后由有界权威的决策预言机（LLM 或人）逐条放行或拒绝 [4]。在三个基准与三个模型上，Kairos 在攻击成功与效用的权衡上优于既有防御；在 AgentDojo 上把 ASR 从 47.0% 降到 2.7%，良性效用保持在无防御 Agent 的水平 [4]。局限：策略需要人工声明可信源，推迟机制引入延迟与预言机瓶颈，结论限于三个基准。

## 6 共同失效模式

综合五项工作，可归纳出三条跨论文的结论，而非五篇工作的并列。

第一，持久化状态下的隐式信任假设系统性失效。五篇论文各自击破一个此前被视为当然的绑定：工具结果与上下文的绑定 [1]、工具描述与良性假设的绑定 [2]、外部内容与指令的隔离 [3][4]、工具参数与语义校验的绑定 [5]。共同点在于：一旦状态跨越单次执行存续或共享，运行时就不再能默认这些绑定成立。

第二，安全指标捕捉的是"被拒绝的攻击"，而非真实风险。低 ASR 可能只是 Agent 静默忽略 [3]；工具描述的隐蔽性可同时骗过自动检测器与人类 [2]；工具在模糊测试之前看似满足文档语义 [5]；重放下最终状态错误率高达 0.649，单动作视角看不出来 [1]。失败方式不被度量，使防御看似有效。

第三，单点判定在上下文相关与状态持续的条件下必然失效。合法动作与攻击第一步在动作时刻无法区分 [4]；同一权重仅改系统提示，ASR 可从 0.2% 跃至 43% [3]；结果过期与隐式环境变化下错误率仍高 [1]。这要求判定必须跨时间、跨动作累积证据，而非在单次调用时点做允许或拒绝。

## 7 防御分层建议

写入层：对工具描述与记忆条目实施来源标注与写入完整性校验，核对描述权限与实际权限的一致性，防止投毒 [2]；为记忆写入记录 provenance 以支持溯源。

运行时层：对工具结果实施显式上下文绑定与有效性检查 [1]；监测需区分"忽略"与"拒绝"，报告中同时披露攻击如何失败与用户任务是否完成 [3]；在工具侧部署语义校验，拒绝违反文档语义的参数 [5]。

边界治理层：在系统边界部署参考监视器，以声明式策略声明可信源，将不确定效果推迟、由有界权威预言机基于 trace 裁决 [4]；跨 Agent 共享记忆时以同一套策略约束读写主体。

## 8 三个开放问题

一、遗忘的正确性如何验证？现有工作几乎不涉及删除语义；TRAP 显示结果过期下错误率仍高 [1]，但"何时可安全遗忘、遗忘后如何回滚"尚无标准——记忆删除是否应保留可审计的删除日志、以便检测到投毒后回滚到污染前的快照，目前没有共识。

二、静默忽略是否可接受？Ignored, Not Refused 证明忽略是低 ASR 的主要来源，且 21.7% 的回合任务未完成 [3]；忽略与拒绝在用户透明度上的含义尚未被回答。如果 Agent 必须显式拒绝，拒绝行为本身又会成为攻击者可学习的信号，拒绝与忽略之间的最优策略尚无理论刻画。

三、跨 Agent 记忆共享的信任如何建立？Kairos 的策略依赖可信源声明 [4]，但多 Agent 共享记忆池时谁写谁负责、如何溯源没有机制——声明本身在动态接入的第三方工具上就难以预先完成；ToFu 表明工具侧语义经常不被执行 [5]，共享工具链上的语义保证更难成立。
