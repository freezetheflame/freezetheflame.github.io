# Case Studies: Vibe-Coded Repos Under Testing

## Purpose

This page catalogs real-world vibe-coded repositories and tracks testing interventions applied to them. Each entry records what was found, what was done, and what was learned.

## Selection Criteria

Candidate repos should show multiple signals of vibe-coding origin:
- Rapid feature velocity inconsistent with team size
- Thin or absent test coverage
- High ratio of open issues to merged PRs
- AI tool markers in commit messages or PR descriptions (e.g., "Claude wrote this", "generated by Cursor")

## Patterns Catalog

As case studies accumulate, extract recurring patterns here:

### Pattern: The Missing Error Handler
Functions that call external APIs without error handling. The happy path works; network failures, timeouts, and bad responses all crash.

### Pattern: The Untyped Boundary
TypeScript repos with `any` at module boundaries. The type system can't help because the AI used escape hatches.

### Pattern: The Orphaned Feature
A feature was vibe-coded, demoed, and abandoned when the next cool thing came along. No tests, no docs, no one knows if it still works.

### Pattern: The Config Cascade
Configuration spread across `.env`, `config.ts`, CLI flags, and hardcoded defaults. No single source of truth. Changing one breaks another.
